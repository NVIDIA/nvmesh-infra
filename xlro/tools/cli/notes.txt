Requirements
    P0 - Support attach/detach (not attach-create for 2.7) (currently only via REST)
    P1 - Forwards compatibility
    P1 - Python3
    P1 - No SDK
    P1 - Multi-Version (same client can run against multiple mgmt versions)
    P2 - Independent packaging, remote run
    P2 - Multi-Manager (connect/disconnect in same run)

Non Requirements:
    Non-syntax help per command?
    Auto-generated attributes?
    Snapshots in 2.7

Design Goals
    - Single source of truth for any given thing
        - validations should be in server
    - Name aliasing/normalization - (camel, snake, dash/underscore, human, etc.; drive vs. disk?)
    - Testability
    - Generalize scan/format (values: e.g., capacity - Units, MAX; enums: e.g., attach-mode, raid-level, etc.)
    - Calculated fields (e.g., targets of volumes)
    - Generalize payload generation? (Template? See attach payload - looping, nesting, mapping, etc.)
    - Future bypass (>FwdCompat, enable using as-yet undeclared, but now supported, properties)
    - Code overrides (when generalization too costly/complex or plain impossible)
    - Remove extra layers (volume -> VolumeCLI -> VolumeAPI) and explicit parameters in APIs
